## 本轮重点 · 更新后「DD 驱动自动退回普通模式」：被拒后重启即自动切回

有用户反馈：更新软件之后，DD 驱动模式自动退回到了普通模式。

排查确认：程序升级对**已装好 DD 驱动的老用户**在代码层面是零变化的（升级不换驱动、不改配置），
"更新后退回普通模式"实际是两类**安全保护被更新的动作触发**了，而它们此前都要靠用户自己
记住"重启后再来手动选一次 DD"——忘了就一直停在普通模式，看起来就像"自动退回没人管"。

### 一、这次修了什么

以下两类拒绝的共同点是：**本次运行无解，重启电脑就自愈**。1.9.11 起程序会在拒绝发生时
自动登记「重启后切回 DD」待办（与卸载 Interception 驱动后的自动切换同一机制），
重启完成后自动升回 DD 驱动模式，**不需要再手动选择**：

- **「旧版 dd63330 驱动仍在系统中运行」**：换新目录安装 / 换新一代驱动时，
  旧一代内核驱动还驻留在系统里（程序退出从不卸载内核驱动，要到重启才摘掉）。
  两代虚拟设备不能同时注入，程序会拒绝并要求重启——现在重启后会自动切回。
- **「驱动与程序自带的不是同一份」**：服务的驱动登记路径指向旧安装目录（目录已删 / 换过位置），
  为避免版本错位导致蓝屏，程序会拒绝并要求重启——现在重启后会自动切回。

三条触发路径（冷启动被拒、手动选择被拒、自动获取装好后被拒）全部落盘待办；
其余失败（缺驱动 / 32 位 / 初始化失败）行为不变，仍走原来的下载引导。

### 二、更新时的两条注意事项（README 已补）

- **先完全退出程序再覆盖 / 换目录**（托盘右键 → 退出）：程序被强制结束时若正用着 DD 驱动，
  下次启动会触发「上次运行未正常结束」崩溃保护、自动退回普通模式——这是防蓝屏的设计，
  在「选项 → 键盘注入」重新选 DD 即恢复
- 程序内「选项 → 检查更新」的自动更新不受影响，退出时序是干净的

## 升级方式

- 1.9.x 用户：程序内「选项 → 检查更新」即可发现并安装 1.9.11（主通道 / 备用通道均可用）
- 也可以直接下载覆盖安装（先退出程序），配置（方案、热键、音量、外观）在
  `%APPDATA%\TheCelestialDiviner\`，升级不丢失
- 配置版本不变（v22），**不做任何迁移动作**，全部设置原样保留

## 已知问题

- **多宏方案 >2 键降级会被旧版清除**（沿自 1.9.6）：降级回 ≤1.9.5 前先在「选项 → 导出配置」备份
- **已设为鼠标侧键的热键在 ≤1.9.6 旧版中失效**（沿自 1.9.7）：降级需重新设置为键盘键
- **Toggle（点按切换）自环方案"按下被吞"**（沿自 1.9.5）：队列深时 Toggle 键的按下可能被
  当成回环吞掉，表现为"点了没反应"；遇到时切一次注入模式或重启可恢复
- **Win11 25H2 上个别用户反馈 DD 驱动"触发按键后运行几秒自动停止"**（沿自 1.9.4）。
  遇到时请把日志发给作者；影响使用可先改用 Interception
