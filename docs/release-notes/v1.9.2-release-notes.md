## 本轮重点 · 把「点一下就能升级」这件事做安全

这次没有新功能，只修一个会让人用不了软件的升级事故，以及让它别再无声发生。

- **事故**：个别用户点了底栏「有更新」，升级完第一次启动就弹「发生内部错误：…类型初始值设定项引发异常」，
  然后就打不开了。原因不是程序逻辑，而是**覆盖安装的结果半新半旧**：目录里缺了
  `System.Text.Json` 依赖链里的某个 dll（或被别的同名旧文件顶替），而旧的更新脚本
  **不管覆盖成没成功，都会把新 exe 拉起来**——半成品被当成成品启动，自然起不来
- **现在更新流程这样走**：
  1. **先验包**：解包后核对主程序、依赖 dll 清单、`exe.config` 是否齐全，有没有 0 字节文件；
     不通过就**当场中止**并说明缺哪个文件——程序继续正常运行，不会退到一半没退路
  2. **先预检**：安装目录不可写（例如放在 `Program Files` 又没权限）立刻提示，而不是等退出后才失败
  3. **先备份**：整份安装目录复制到 `%TEMP%`，覆盖失败就**自动回滚**并重启原版本——
     哪怕更新没成，你也还有一个能用的程序
  4. **覆盖带判定**：改用 robocopy 并检查退出码，失败会重试（最多 4 轮，每轮 1 秒）；
     覆盖完再逐项清点关键文件，缺一个就回滚。旧的 xcopy 脚本把输出和退出码一起丢掉了，
     这是"半新半旧还能启动"的根源
  5. **结果有回执**：更新成败写入状态标记，下次启动如实告诉你——「已回滚到当前版本（错误码 N）」
     或「更新到 X 没有生效」，并给出手动下载指引；成功则只记日志，不打扰
- **出错提示不再只有一句「发生内部错误」**：现在会展开内层原因（例如具体是哪个文件加载不到），
  属于运行环境 / 依赖问题（缺 dll、版本不匹配、被杀软隔离）时直接给出修复步骤：
  完全退出 → 删除程序目录（配置在 `%APPDATA%`，不受影响）→ 重新解压完整发布包 → 检查杀软隔离区
- **启动加了一道依赖自检**：先真实跑一遍配置的序列化 + 反序列化，依赖不可用就列出缺哪个文件并给出
  修复步骤，而不是等进了界面再莫名崩溃
- **公告区归位**：注释区公告不再承载版本更新总结与功能提示。DD 驱动下载这类提醒只在你真正发起下载时
  出现——确认框里说明一次，进度行实时显示第几次失败、多久后重试

## 升级方式

- 1.9.1 及更早版本：程序内「选项 → 检查更新」即可发现并安装 1.9.2（主通道 / 备用通道均可用）
- 也可以直接下载完整包，**解压到新目录**运行；配置（方案、热键、音量、外观）在
  `%APPDATA%\TheCelestialDiviner\`，升级不丢失
- **如果你之前遇到过"升级后打不开"**：删除旧程序目录后重新解压完整包即可，不用动配置

## 已知问题 / 说明

- 自动更新的回滚依赖 `%TEMP%` 上的备份：安装目录体积超过 200MB 时不再备份（会记日志），
  这种情形下更新失败不会回滚，需手动下载完整包
- 覆盖安装不会删除你放在程序目录里的其他文件（例如自己下载的 `dd63330.dll`），
  **DD 驱动不属于发布包**，升级后不需要重新获取
- 若更新脚本被安全软件拦截（表现为"点了更新但版本没变"），程序下次启动会明确提示，
  此时请到 Release 页手动下载完整包

## 使用说明

- 解压后进入同名文件夹即可使用，请以**管理员身份**运行（低级键盘钩子与注入驱动均需要）
- 免费版 DD 驱动加载时需要联网授权一次；发布包不含闭源 DD 驱动，首次使用 DD 模式时按程序引导一键获取
- Interception 为**可选**路线，文件随包附带、安装不需要联网
