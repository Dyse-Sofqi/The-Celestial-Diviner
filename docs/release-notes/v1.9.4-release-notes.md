## 本轮重点 · 一个「点了没反应」的按钮，牵出一句写错类型的时间判断

这一版没有新玩法，只修一个很隐蔽的 bug —— 它让「从左侧键盘增删按键方案」这枚按钮
在特定条件下**彻底点不动**，而且看不出任何异常：不变灰、不报错、日志里也没有痕迹。

### 你会看到的现象

- 点「从左侧键盘增删按键方案」，左侧键鼠区**没有变灰**（正常应该整片降到半透明 + 悬停高亮）
- 点左侧的键位也没有任何反应，加不了新方案
- 同一台机器上「设置全局开关热键」「切换方案热键」「独立关闭热键」也一样点不动
- 但是：方案列表里的勾选启用 / 停用、修改按压与间隔、删除按钮**全部正常**
  —— 因为坏的只是"进入录入状态"这一道门，方案数据本身没有被动过

### 原因

进入录入态之前有一道 150ms 的冷却（防止"退出管理态"的那一次点击又把管理态立刻打开）。
它用系统运行毫秒数 `Environment.TickCount` 相减来判断，而这是一个 32 位整数：

- 系统连续运行满 **24.9 天**，它会**回绕成负数**
- "上次退出时刻"的初值是 `0`，于是 `负数 - 0` 恒小于 150 → 每次点击都被判成"刚退出、还在冷却"
- 最要命的是它**自己解不开**：要记录"上次退出时刻"，得先成功进入一次管理态，
  而进入管理态正被这句判断挡住

Windows 10/11 的「快速启动」不会清零这个计数，长期不关机、经常睡眠唤醒的机器很容易
落进"开机 24.9~49.7 天"这个区间 —— 它占整个 49.7 天周期的一半，所以是"有的人从来没事，
有的人一开就是坏的"。落进这个区间时**必现**，重启电脑（uptime 归零）后立刻恢复。

### 已修

- 冷却判断改成无符号差值，跨越回绕点仍然是真实的毫秒数；三个热键录入入口同样修正
- 同一根源的另外两处键帽问题一并修掉：键帽刷新节流会把下一次重绘排到约 **24.8 天后**
  （画面看起来冻结），键帽还会被永久判成"发射中"（不淡出、不跟随快照）
- 交互上补两道兜底：
  - 管理态下**再点一次这枚按钮就是退出**，不再只能靠"点击键鼠区空白处"
    （全局鼠标钩子没装上时，以前会退不出来）
  - 正在录热键时点它，会直接切换到方案管理，不再静默无反应

## 关于「方案全部消失」的说明

这次修复针对的是"加不进去"，**不会**造成已保存的方案丢失，也不会把它变回来。
如果你打开程序发现方案列表是空的，请先确认两件事：

1. 面板顶部的档位是不是 **①**（默认切换方案热键是 F10，游戏里容易误触，切到空档位就什么都看不到）
2. 「开关模式 / 按压模式」标签、以及下面「常规开关 / 轮转开关 / 双宏开关」分区是否选对
   —— 列表只显示"当前档位 + 当前模式 + 当前分区"的方案

两处都确认过仍然是空的，请把 `%APPDATA%\TheCelestialDiviner\config.json` 和
`logs\app-当天日期.log` 发给作者，日志里能直接看出是"配置解析失败被重置"还是"启动迁移删除了旧格式方案"。

## 升级方式

- 1.9.x 用户：程序内「选项 → 检查更新」即可发现并安装 1.9.4（主通道 / 备用通道均可用）
- 也可以直接下载覆盖安装，配置（方案、热键、音量、外观）在 `%APPDATA%\TheCelestialDiviner\`，升级不丢失
- 配置版本仍是 v21，**不做任何迁移动作**：方案、档位、热键、驱动选择全部原样保留
