## 本轮重点 · 多了一条物理级路线，而且会按你的系统给建议

- **新增「Interception 驱动」（开源的物理级注入路线）**：[oblitum/Interception](https://github.com/oblitum/Interception)
  （作者 Francisco Lopes，LGPL 3.0）。它和 DD 一样属于内核层注入、事件不带「模拟按键」标记，
  但**开源、可核对来源与签名**，也不需要 DD 免费版那次联网授权
  - **随安装包附带**官方原版文件（`interception\` 目录，含 LGPL 全文），点一下就开始装，**不需要联网**
  - 安装 = 校验官方 dll 指纹 → 调**官方安装器**：不改、不重签、不自己写安装逻辑
  - 装完**必须重启**（键盘类过滤驱动要重启才挂上），程序会记住这次选择，**重启后自动切到该模式**
  - 它只发按键、不接管物理键盘：程序卡死也不会影响你正常打字
- **两个驱动在系统层互斥（实测）**：装了 Interception 之后，DD 注入的按键一条都进不了系统
  （`DD_btn` 初始化成功但注入全丢，与程序无关，是键盘类过滤驱动把 DD 虚拟设备挡住了）。
  所以在菜单里点 DD 时，如果检测到 Interception 还在，会**弹窗说明并询问是否卸载**，
  确认后自动卸载并登记「重启后自动切回 DD」——重启完就是 DD，不用再手动选一次
- **首次启动会按系统环境给一次建议**：读系统真实版本（RtlGetVersion）、
  内核完整性三项开关（内存完整性 / 硬件堆栈保护 / Smart App Control）、
  键盘栈上已有的过滤驱动，判断这台机器该走哪条路线并说明理由；也可以自己改选
  - 典型结论：Win11 25H2 及以上 → 推荐 Interception（DD 有 0x50 蓝屏风险）；
    24H2 及更早 → 推荐 DD（免重启）；内核完整性开着 → 两条都装不上，提示先关开关
  - 键盘栈上若有第三方过滤驱动，会点名提示（这类是「按键无反应 / 停不下来」的常见来源）
- **修复 · 开关按一次停不下来**：回环名额在回环丢失后会滞留并吞掉你的物理按键，
  加上「按住表」只能靠松手事件清除，于是一旦漏一次松手，这个键就再也停不下来。
  现在：名额超时即丢弃（按实测往返自适应，DD≈170ms / Interception≈0~16ms）、
  按住表超时自愈（且会先确认物理键确实已松开，长按开关键不会被误判成第二次按下）、
  切换注入模式时两套状态一并清空

## 升级方式

- 1.9.0 用户：程序内「选项 → 检查更新」即可发现并安装 1.9.1（主通道 / 备用通道均可用）
- 直接下载覆盖安装即可，配置（方案、热键、音量等）在 `%APPDATA%\TheCelestialDiviner\`，升级不丢失

**正在用 DD 驱动的老用户，升级后行为不变（这一条我们专门做了保护）：**

- 配置里的注入模式原样保留，不会被强制切换
- 若当前就是 DD 模式且 DD 可用，程序判定「已是本机最优路线」，**连首次导引弹窗都不会出现**
- DD 的连发时序、回环消除、方案与热键全部不变；新增的只是「防按键被吞」的兜底
- 除了你自己主动去装 Interception，系统里不会多出任何驱动

## 已知问题 / 说明

- **Interception 与 DD 只能二选一**：要换回去必须先卸载另一个并重启。卸载入口在
  「选项 → 键盘注入 → 卸载 Interception 驱动…」，程序会自动登记重启后的切换
- **内核完整性（HVCI / 内存完整性）开启时**：两条物理级路线都加载不了，只能用普通 / 扫描码 / 消息模式；
  Interception 失败方式是「装不上」，DD 在 25H2 上则可能直接 0x50
- 现场排查：`tools/diag-interception.ps1`（只读）一次打出库指纹 / 签名、键盘类 UpperFilters、
  System32 驱动签名、服务状态、`create_context` 结果、HVCI 与 Secure Boot

- 解压后进入同名文件夹即可使用，请以**管理员身份**运行（低级键盘钩子与注入驱动均需要）
- 免费版 DD 驱动加载时需要联网授权一次；发布包不含闭源 DD 驱动，首次使用 DD 模式时按程序引导一键获取
- Interception 为**可选**路线，文件随包附带、安装不需要联网
