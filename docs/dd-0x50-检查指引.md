# DD 驱动蓝屏（0x50）现场检查指引

面向：客户出现 `PAGE_FAULT_IN_NONPAGED_AREA (0x50)` / 失败的操作 `dd63330.sys` 时使用。
配套脚本：`tools/diag-dd-driver.ps1`

---

## 一、让客户跑一次采集（约 1 分钟）

1. 把 `diag-dd-driver.ps1` 发给客户（单文件，无需安装）。
2. 右键 →「使用 PowerShell 运行」；或在该目录 shift + 右键 →「在此处打开 PowerShell 窗口」，执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File ".\diag-dd-driver.ps1"
```

3. 脚本会申请管理员权限（UAC 点是），跑完在**桌面**生成：
   - `dd-diag-<机器名>-<时间>.txt` —— 文本报告
   - `dd-diag-<机器名>-<时间>.zip` —— 同上 + 最近 3 份应用日志 + 最近 2 个 minidump

4. 让客户把 zip 发回来即可，不用再问东问西。

脚本只做查询：不安装、不删除、不启动任何驱动，唯一的写操作是把报告/日志/转储复制到输出目录。

---

## 二、拿到报告先看这 5 处

| # | 报告小节 | 看什么 | 命中意味着 |
|---|---|---|---|
| 1 | 1. 系统版本 | `判定` 行是否 25H2（Build 26200+） | 25H2 对老式键盘过滤驱动最不友好 |
| 2 | 2. 内核隔离 | 内存完整性是否「已开启」、Kernel Shadow Stacks、Smart App Control | 三者任一开启，都可能在驱动执行代码页时直接 0x50 |
| 3 | 5. dd63330 服务 | `ImagePath` 指向哪里、`映像文件存在` 是否为 False | 服务是残留 / 指向 %TEMP% → 加载的驱动身份不明，头号嫌疑 |
| 4 | 6. 应用日志 | 「已加载 DD 驱动库」的路径 + 日志最后 25 行 | 最后一行若停在「驱动已启动」之后，说明崩在驱动内部 |
| 5 | 7. 文件指纹 | 带 `<== 程序当前加载的 DLL` / `<== 服务 ImagePath` 标记的两份 `.sys` 哈希是否一致 | 多份不同哈希 = 驱动与 DLL 版本不配套 |

## 三、25H2 专属的三个开关

25H2（26200）相对 24H2 进一步收紧了内核代码完整性，下面三项要单独确认：

1. **内存完整性（HVCI）**
   设置 → 隐私和安全性 → Windows 安全中心 → 设备安全性 → 内核隔离 → 内存完整性。
   25H2 全新安装常默认开启。老驱动被剥离代码页后，典型报错就是 0x50（参数 2 = `0x10`，执行操作）。

2. **内核模式硬件强制堆栈保护（Kernel Shadow Stacks）**
   注册表：`HKLM\SYSTEM\CurrentControlSet\Control\DeviceGuard\Scenarios\KernelShadowStacks\Enabled`。
   开启后驱动必须遵守 shadow stack 约定，未适配的第三方驱动会直接异常。

3. **Smart App Control**
   注册表：`HKLM\SYSTEM\CurrentControlSet\Control\CI\Policy\VerifiedAndReputablePolicyState`
   （`1` = 强制，`2` = 评估，`0` = 关闭）。25H2 全新装机默认就在评估/强制状态，会拦没有信誉记录的驱动。

> 注意：这三项造成的现象经常是「加载失败」而不是蓝屏；但只要驱动已经进了内核、后续某个代码路径被拒，就会以 0x50 收场。

## 四、客户立即止血（10 分钟内可恢复可用）

```cmd
:: 1. 关程序后，停止并删除残留服务（提示"服务不存在"就跳过）
sc stop dd63330
sc delete dd63330

:: 2. 确认删干净
sc query dd63330
```

3. 删除这三处的 `dd63330.dll` / `dd63330.sys`：
   - 程序目录
   - `%APPDATA%\TheCelestialDiviner\drivers`
   - `%TEMP%`

4. 重新打开程序 →「选项」→「键盘注入」选 **扫描码 / 消息** 模式（不加载内核驱动），连发照常可用。

5. 若 25H2 上仍蓝，按第三节关闭内存完整性 / Smart App Control 后再试；仍蓝则说明这台机器必须放弃 DD 模式。

## 五、拿到 dump 后（研发侧）

```
windbg -z C:\Windows\Minidump\<最新>.dmp
0: kd> !analyze -v
0: kd> !sysinfo machineid      // 确认补丁级别
0: kd> kb                      // 栈上是否出现 DD 的函数
0: kd> lmvm dd63330            // 驱动映像基址 / 时间戳，确认是哪一版
```

判读要点：

- **参数 2**：`0` 读、`2` 写、`0x10` 执行。出现 `0x10` 时，优先怀疑 HVCI / Shadow Stack 把代码页剥了。
- **参数 4**：`0x0` 已释放的页表项（典型的"指针指向已释放内存"）、`0x2` 无有效页表项、`0xF` 内核代码去访问用户态地址（键盘过滤驱动最常见的一种）。
- 栈上若同时出现 `kbdclass` / `i8042prt` / 其他键盘过滤驱动，说明是驱动叠加冲突，不是 DD 单独的问题。
- 每次蓝屏都记录 `dd63330` 的映像时间戳，和客户机器上实际存在的 `.sys` 哈希对得上，才能确认是同一份二进制在崩。

---

## 六、结论口径

对客户可以这么说：

> 这不是您的电脑坏了，也不是中病毒。蓝屏发生在"键盘注入"功能依赖的第三方内核驱动（dd63330.sys）内部——它在 Windows 11 25H2 上访问了一块非法内存。我们把驱动模式关掉，改用普通模式，连发功能不受影响，系统也不会再蓝屏。驱动模式的问题我们会在后续版本里单独处理。
